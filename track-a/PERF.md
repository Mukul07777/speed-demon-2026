**Final: 83.87 points on the board for the current code (b512e55 plus the line cut of step 22): run-b7e4efca914a, T 21.4 ms, M 20.5 MB. S 344 by default rustfmt on the current code (351 on the board's count).** From the first Rust version: 72.8 ms to about 21.6, 63.8 MB to about 20, 67.83 to 83.87 points.

Key ideas, in order of what they were worth:

- A branch-free parse. A newline pass with one unconditional store per 32-byte step, then each line read from fixed offsets and back from its newline with SWAR arithmetic, so line length never steers a branch.
- Each line becomes one 4-byte row (endpoint id, error bit, 20-bit latency; the 1% of larger latencies escape to a second row) in a fixed area per hour, so nothing is regrouped after parsing.
- Per hour, a two-pass radix sort by latency inside the hour's own pages, then the rows are dealt out by endpoint, so every endpoint's latencies come out sorted and a percentile is one array read.
- Memory follows the work: claim pages are dropped after parsing, an hour's text is built over its own rows, and each hour is written with `pwrite` at its offset by whichever thread finds it ready, then its pages go back.
- Start-up and teardown: static linking, and no page population, which only paid off on the box.
- Endpoints by a 64-bit hash alone (an AES-round hash of the masked first and last 32 bytes), in one shared table that is read-only after the first moments.
